# Plan: Let the user turn the screenshot guard (FLAG_SECURE) on or off

**Status:** completed

## The issue

Today the app always blocks screenshots and screen recording on sensitive screens
(History and its detail sheet, Result, the API keys screen, the AirQR screens, the
export/backup dialog and the batch review sheet). This uses Android's `FLAG_SECURE`.

The user has no choice. Some people want to take a screenshot of a scan result or
their history, or record the screen for a demo. The user wants a switch in Settings
so they can decide.

## How it works now

- `lib/services/screen_security_service.dart` keeps a counter of open sensitive
  screens. When the first one opens it turns `FLAG_SECURE` on (method channel
  `in.sreerajp.qr_studio/window`, method `setSecure`). When the last one closes it
  turns it off.
- `lib/widgets/secure_screen.dart` (`SecureScreen`) wraps each sensitive screen and
  calls `acquire()` / `release()`.
- `MainActivity.kt` adds or clears the window flag. No native change is needed.

## The fix

1. **Service** (`services` layer) — `ScreenSecurityService` gets an `enabled` flag
   (default `true`) and a `setEnabled(bool)` method.
   - The counter keeps working as before, even when the guard is off.
   - The real flag is on only when `enabled` is true **and** at least one sensitive
     screen is open.
   - Changing `enabled` while a sensitive screen is open applies at once (the
     Settings screen itself is wrapped in `SecureScreen`, so this case is real).
   - Calls still never throw.

2. **Provider** (`providers` layer) — new `ScreenSecurityProvider`
   (`ChangeNotifier`), built like `AppLockProvider`:
   - Reads `SharedPreferences` key `screen_security_enabled` (default `true`, so
     current users keep today's safe behavior).
   - Pushes the value to `ScreenSecurityService.instance` on load and on change.
   - `setEnabled(bool)` saves the value and notifies listeners.
   - "Delete all data" clears preferences, so after a wipe the guard is back on
     (safe default). No change to `DataWipeService` is needed.

3. **main.dart** — register `ScreenSecurityProvider(prefs: prefs)` in the
   `MultiProvider` list (one line).

4. **Settings → Privacy screen** — add a new card with a `SwitchListTile` between
   "App lock" and "Delete all data":
   - icon `Icons.screenshot_monitor`
   - title: "Screenshot guard"
   - subtitle: explains that when on, screens that show scans, history, secrets or
     API keys cannot be captured by screenshots or screen recording, and are blank
     in the recent-apps view.

5. **Localization** — new keys in `app_en.arb` (with `@` descriptions),
   `app_ml.arb`, `app_sa.arb`, then `flutter gen-l10n`:
   - `labelScreenshotGuard` — "Screenshot guard" (short, under 20 chars)
     - ml: "സ്ക്രീൻഷോട്ട് സംരക്ഷണം"
     - sa: "पटलचित्र-रक्षणम्"
   - `descScreenshotGuard` — "Block screenshots and screen recording on screens
     that show scans, history, secrets or API keys. They also stay blank in recent apps."
     - real Malayalam and pure Sanskrit translations (no Hindi words), following the
       words already used in `helpGuideHistoryBiometricsBullet2`.
   - Update the existing texts that say screenshots are always blocked, so they stay
     true: `descFeatureBiometricGuard` and `helpGuideHistoryBiometricsBullet2` get a
     short ending such as "You can turn this off in Settings › Privacy." in all three
     languages.

6. **Tests**
   - `test/services/screen_security_service_test.dart`: flag not set when disabled;
     turning it on while a screen is open sets the flag; turning it off while a screen
     is open clears it; counter still correct.
   - New `test/providers/screen_security_provider_test.dart`: default is on; loads a
     saved `false`; `setEnabled` saves and updates the service.
   - `test/screens/settings_screen_test.dart`: the Privacy screen shows the switch,
     and tapping it changes the setting (add the provider to the test tree).

7. **Docs** — update so they match the new behavior:
   - `docs/security.md` §10.1 (guard is on by default, user can turn it off), the
     test table row, and the risk/acceptance notes.
   - `docs/architecture.md` (the "Screenshot protection" decision row, and the
     providers list).
   - `docs/project_structure.md` (new provider file).
   - `docs/release_process.md` checklist: check the switch works both ways on a device.
   - `CHANGELOG.md`: one line under the next version.

## Choices made (tell me if you want them different)

- **Default is ON.** Current users keep the same protection until they choose to
  turn it off.
- **No fingerprint check to turn it off.** Anyone holding the unlocked app can turn it
  off. If you want, when App lock is on, turning the guard off could ask for
  fingerprint/face first (like App lock itself does).
