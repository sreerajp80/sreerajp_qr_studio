# Plan: AirQR transmitter as its own menu item

**Status:** completed

## What the issue is

Today the AirQR transmitter (the screen that sends data as moving QR codes) can only be
reached from inside the AirQR receiver screen, through a small QR icon in its top bar.
This is hard to find. The user wants the transmitter to be its own item in the scanner's
"more options" (⋮) menu, and not shown inside the receiver.

## Files to be changed

- `lib/screens/scanner_screen.dart` — add the new menu item.
- `lib/screens/air_qr_screen.dart` — remove the transmitter button from the top bar.
- `lib/l10n/app_en.arb`, `lib/l10n/app_ml.arb`, `lib/l10n/app_sa.arb` — remove the
  `tooltipAirQrTransmitter` key, which is no longer used anywhere.
- `lib/l10n/gen/*` — regenerated by `flutter gen-l10n` (not hand-edited).
- `test/screens/air_qr_screen_test.dart` — add a check that the transmitter button is gone
  (if the test setup allows it simply).

## Plan for the fix

1. **Scanner menu** (`scanner_screen.dart`): add a new item right after "AirQR receiver":
   - route: `/air_qr_transmitter` (already registered in `main.dart`),
   - icon: `Icons.cast` (so it does not look like CodeForge, which uses `Icons.qr_code_2`),
   - label: existing key `l10n.titleAirQrTransmitter` (already translated in all three
     languages — no new strings).
   It goes through the existing `_navigateToRoute`, which already stops the scanner camera
   before opening a screen and starts it again on return.
2. **Receiver screen** (`air_qr_screen.dart`): remove the `IconButton` with the
   `Icons.qr_code_2` icon (and its camera stop/restart code). The reset button stays.
3. **Strings**: remove `tooltipAirQrTransmitter` (and its `@` entry in English) from all
   three ARB files, then run `flutter gen-l10n`.
4. **Other entry points stay as they are**: Settings → "AirQR sync" and the export dialog's
   "Beam via AirQR" button still open the transmitter.
5. Run `dart format .`, `flutter analyze`, `flutter test`.
6. Write a change log in `change_log/`.
