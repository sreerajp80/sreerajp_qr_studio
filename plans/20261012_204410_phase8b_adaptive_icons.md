# Phase 8b — Android adaptive launcher icon, monochrome layer, dev badge (option B)

**Status:** completed

Part of [plans/20261012_191914_guidelines_compliance_roadmap.md](20261012_191914_guidelines_compliance_roadmap.md)
(gap G2). The user chose **option B**: make the icon layers from the existing artwork, with no
new artwork and no new Dart package.

## What the issue is

Engineering standard §17.5: "Android MUST ship an adaptive icon (foreground + background layers)
and SHOULD ship a monochrome layer for themed icons", and "Flavor builds SHOULD use a visibly
different icon (e.g. a 'DEV' badge)". Today:

- `android/app/src/main/res/mipmap-*/ic_launcher.png` are plain square PNGs; there is no
  `mipmap-anydpi-v26/ic_launcher.xml`, so Android 8+ shows the square picture squeezed into
  the launcher shape, and Android 13+ cannot theme it.
- The dev flavor uses the same icon as prod.
- The only source is `assets/app_icon.png` (1024×1024, no transparency): a white rounded square
  (black outside the corners) with a blue/teal circle emblem in the middle; the coloured part
  spans about x 164–860, y 152–872 (a soft grey shadow sits under it).

## Files to be changed

- `tool/generate_launcher_icons.py` — new: the generator (Python 3 + Pillow; build-time only,
  not part of the app). Committed so the icons can be made again the same way.
- `android/app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml` — new adaptive icon.
- `android/app/src/main/res/values/ic_launcher_background.xml` — new colour resource (white).
- `android/app/src/main/res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher_foreground.png`
  and `ic_launcher_monochrome.png` — new (108 dp at each density: 108/162/216/324/432 px).
- `android/app/src/dev/res/mipmap-*/ic_launcher_foreground.png` and
  `android/app/src/dev/res/mipmap-*/ic_launcher.png` — new dev-only copies with a "DEV" badge
  (flavor resources override `main`).
- `android/app/src/main/res/mipmap-*/ic_launcher.png` — unchanged (still used on Android 7,
  `minSdk 24`).
- `docs/architecture.md` (UI/assets part) and `docs/project_structure.md` — where the icons come
  from and how to make them again.
- `change_log/<timestamp>_phase8b_adaptive_icons.md` — new.

## Plan for the fix

1. **Generator script** (`tool/generate_launcher_icons.py`, run from the project root):
   - Read `assets/app_icon.png`; turn the black corner pixels white, so only the white square
     and the emblem remain.
   - **Background layer:** plain white, as `@color/ic_launcher_background` (#FFFFFF), the same
     white as the icon.
   - **Foreground layer:** find the emblem by its coloured pixels (the grey shadow is left out),
     centre it on a white 108-dp canvas and scale it so the whole emblem, ticks included, fits
     inside the 66-dp safe circle that every launcher shape keeps. Save one PNG per density.
   - **Monochrome layer:** a transparent PNG where the coloured parts of the emblem (circle fill
     and ticks) are solid and the white parts (QR modules and ring) are cut out. Android 13+
     tints this shape with the user's theme colour. Same size and position as the foreground.
   - **Dev badge:** the foreground (and the legacy square icon) with a red rounded "DEV" label
     across the lower part of the emblem, inside the safe circle. The letters are drawn as
     simple shapes, so no font file is needed (no font licence question, §17.4).
   - The script prints every file it writes; it never touches `assets/` or other files.
2. **Adaptive icon XML** (`mipmap-anydpi-v26/ic_launcher.xml`):
   `<adaptive-icon>` with `background` = `@color/ic_launcher_background`, `foreground` =
   `@mipmap/ic_launcher_foreground`, `monochrome` = `@mipmap/ic_launcher_monochrome`. Android
   8–12 ignore the monochrome line; Android 7 keeps using the existing PNGs. The manifest
   already points at `@mipmap/ic_launcher`, so it does not change.
3. **Look check** — I open the generated foreground, monochrome and dev images and show them to
   you (as pictures in chat, plus a preview of each in a circle and a squircle mask) before
   building.
4. **Verify** — `flutter build apk --flavor dev --debug` and `flutter build apk --flavor prod
   --debug` (both flavors, because flavor resources change); check with `aapt2 dump resources`
   (from the Android SDK build tools) that the APKs contain the adaptive icon and, for dev, the
   badge foreground. Then `android\gradlew --stop` and end leftover `GradleDaemon` /
   `KotlinCompileDaemon` processes. No install on any device. `flutter analyze` and
   `flutter test` are run too (no Dart change expected).
5. **Docs** — note in `docs/architecture.md` that launcher icons are generated by
   `tool/generate_launcher_icons.py` from `assets/app_icon.png`, and how to run it.

## Risks

- The monochrome shape is made by colour threshold, so fine edges may look a little rough; it is
  only used when the user turns on themed icons (Android 13+).
- The foreground keeps a white square behind the emblem, which matches the white background
  layer, so it looks the same in every launcher shape.
- Store listing icon (512×512 for Play) is not part of this change.
