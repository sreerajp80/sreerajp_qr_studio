# Fix Gaps 10–12: Sanskrit history crash, AR mode switch, AirQR camera blocked

**Status:** completed

These three problems were found by the new screen tests while implementing
[20261010_210523_gap_analysis_fixes.md](20261010_210523_gap_analysis_fixes.md)
(see its change log
[change_log/20261010_212744_gap_analysis_fixes.md](../change_log/20261010_212744_gap_analysis_fixes.md)).
The CodeForge chip-row wrap is **not** part of this plan.

## Gap 10 — History screen crashes in Sanskrit

**Issue.** `lib/screens/widgets/history_card.dart` formats the scan time with
`DateFormat.yMMMd(locale)` and `DateFormat.jm(locale)`, using the app
language. The `intl` package has date data for English and Malayalam but
**not** for Sanskrit (`sa`). So in Sanskrit it throws `Invalid locale "sa"`
and every history card fails to build (red error box in debug, grey box in
release). This is the only place in `lib/` that uses `DateFormat`.

**Fix.**
- Add one small helper (layer: l10n, next to the other locale helpers):
  `lib/l10n/date_format_locale.dart` with
  `String dateFormatLocale(String localeName)`. It returns `localeName` when
  `DateFormat.localeExists(localeName)` is true, else `'en'`. This matches
  the Sanskrit Material delegates, which also fall back to English for
  dates.
- `history_card.dart` uses `dateFormatLocale(l10n.localeName)` for both
  formats. The rest of the text around the date (`historyTimestamp`) stays
  in Sanskrit.
- Tests:
  - New `test/l10n/date_format_locale_test.dart`: `en` → `en`, `ml` → `ml`,
    `sa` → `en`, unknown → `en`.
  - The existing Sanskrit case in `test/screens/history_screen_test.dart`
    (failing today) must pass.

## Gap 11 — AR CodeVision mode cannot be changed

**Issue.** `ArCodevisionProvider` has `setHudMode` and two modes:
**Warehouse** (price/batch info, select and Batch Copy) and **Safety**
(green/red link-safety badge per code). `docs/features.md` and the Help
screen describe both. But no widget calls `setHudMode`, so the app always
stays in Warehouse mode and Safety mode can never be used.

**Fix.**
- `lib/screens/ar_codevision_screen.dart`: add a two-part switch
  (`SegmentedButton<ArHudMode>`) under the app bar title (`AppBar.bottom`):
  "Warehouse" and "Safety", each with an icon and a tooltip. It is shown in
  every state, including when camera permission is missing, so the user can
  see the choice.
- `lib/providers/ar_codevision_provider.dart`: when the mode changes, clear
  the selection (`_selectedTargetIds`), because the selection and Batch Copy
  bar exist only in Warehouse mode. Nothing else changes; link safety
  checks already run for codes that hold a link.
- The mode is not saved between visits (same as today: it starts in
  Warehouse mode).
- New ARB keys in all three languages (labels ≤ 22 characters, Sanskrit
  Hindi-marker rule, `@key` descriptions in English):
  `arModeWarehouse`, `arModeSafety`, `arModeWarehouseTooltip`,
  `arModeSafetyTooltip`.
- Docs: remove the "no control to switch modes yet" note from
  `docs/features.md`.
- Tests:
  - `test/providers/ar_codevision_provider_test.dart`: changing mode clears
    the selection; setting the same mode again changes nothing.
  - `test/screens/ar_codevision_screen_test.dart`: the switch shows both
    modes in all three languages; tapping "Safety" changes
    `provider.hudMode`; each segment has a tooltip.

## Gap 12 — AirQR receiver shows "Initializing…" forever when the camera is blocked

**Issue.** `lib/screens/air_qr_screen.dart` starts the camera without asking
for permission first. If permission is denied, or the camera cannot start,
the camera view's error builder only shows "Initializing…". The user gets
no message and no way to fix it. The Scanner and AR screens already ask for
permission at point of use and show a message with a button.

**Fix.**
- Ask for camera permission when the AirQR receiver opens, the same way the
  Scanner and AR screens do (`Permission.camera.request()`). Create and
  start the camera controller only when permission is granted.
- When permission is denied: show the camera icon, the existing
  `scanCameraPermissionRequired` text, and the existing `grantPermission`
  button. The button asks again; if granted, the camera starts.
- When the camera itself fails (no camera, or a start error), the error
  builder shows a clear message and a "Try again" button that restarts the
  camera. A permission error reported by the camera plugin shows the
  permission message above.
- The HUD panel, reset button and the rest of the screen keep working as
  today.
- New ARB keys in all three languages: `cameraStartFailed` ("Camera could
  not start"), `cameraNotFound` ("No camera found on this phone"),
  `cameraRetryButton` ("Try again").
- Docs: in `docs/security.md`, the `CAMERA` row's "Requested when" lists the
  Scanner, AR CodeVision and AirQR receiver screens.
- Tests (`test/screens/air_qr_screen_test.dart`, and the test helper):
  - `test/helpers/test_app.dart`: the platform fake gets an option to answer
    "granted" instead of "denied".
  - Denied: the permission message and button show in all three languages;
    the button asks again.
  - Granted, but no camera in the test: the "could not start" message and
    the "Try again" button show; tapping it tries to start again.
  - The existing stream progress and reset tests still pass.
