# Release build script with SHA-256 checksums

**Status:** completed

## The issue

- `tool/build_release.sh` builds the release, but it leaves Flutter's default file names
  (`app-arm64-v8a-prod-release.apk`, `app-prod-release.aab`), which say nothing about the
  version.
- `flutter build apk` writes a `.sha1` file next to each APK. SHA-1 is weak, and Flutter has no
  SHA-256 option. The direct-download channel must publish SHA-256 checksums
  (`docs/release_process.md` §12), and today that is a manual step.
- `flutter build appbundle` writes no checksum at all.
- The `.sh` script needs Git Bash; the maintainer works in PowerShell on Windows.

## Facts checked in this project

- Flutter SDK in use: 3.50.1 (`flutter --version`).
  `packages/flutter_tools/gradle/src/main/kotlin/tasks/CopyFlutterApksTask.kt` names APKs
  `app[-<abi>][-<flavor lower case>]-<mode>.apk` in `build/app/outputs/flutter-apk/`.
  `lib/src/android/gradle.dart` writes `<apk>.sha1` after Gradle finishes, and finds the bundle
  at `build/app/outputs/bundle/<flavor><Mode>/app-<flavor>-<mode>.aab`. So the work must happen
  in a script that runs after `flutter build`, not in a Gradle task.
- Flavors (`android/app/build.gradle`): `dev` and `prod`. Production flavor: `prod`.
- ABIs built (`abiFilters`): `arm64-v8a`, `armeabi-v7a`, `x86_64`.
- `pubspec.yaml` version: `4.1.12+46` (has a `+build` part).
- `--dart-define=BUILD_DATE` (passed by the `.sh`) feeds `AppConstants.buildDate`, which no
  screen reads. The About screen uses `kBuildDate` from `build_date.g.dart`, which the Android
  build regenerates. The new script still passes `BUILD_DATE` so behavior does not change; the
  dead constant can be cleaned up in a separate change.
- `docs/guidelines/` is a git submodule — not touched.

## The fix — `tool/build_release.ps1`

Options:

| Option | Values | Default |
|---|---|---|
| `-Name` | base file name, `^[A-Za-z0-9._-]+$` | required, no default |
| `-Target` | `apk`, `aab` | required |
| `-Flavor` | `dev`, `prod` | `prod` |
| `-Mode` | `release`, `profile`, `debug` | `release` |
| `-NoSplit` | switch: one universal APK | off |
| `-NoObfuscate` | switch: no `--obfuscate` / `--split-debug-info` | off |
| `-SymbolsDir` | path for `--split-debug-info` | aab: `build/symbols/android-<flavor>-<version>/`; apk: `build/symbols/android-<flavor>-<version>-apk/` |

Steps, in order:
1. Read `version: x.y.z+n` from `pubspec.yaml`; stop with a clear message if `+n` is missing.
2. Check options and refuse before running Flutter:
   - `-NoObfuscate` with `prod` + `release`;
   - `-SymbolsDir` when the build is not obfuscated;
   - `-NoSplit` with `prod` + `release` (decision A);
   - `-SymbolsDir` must resolve inside `build/`.
   Debug mode drops the obfuscate flags automatically, with a message. `-NoSplit` with `aab`
   prints "ignored".
3. Delete old Flutter-named outputs for this flavor/mode (and their `.sha1`).
4. Run `flutter build apk|appbundle --flavor <f> --<mode> [--split-per-abi] [--obfuscate
   --split-debug-info=<dir>] --dart-define=BUILD_DATE=<yyyy-MM-dd>`. Non-zero exit → stop,
   rename and hash nothing.
5. Rename each output to `<Name>-[<abi>-]v<x.y.z>_<n>-<flavor>-<mode>.<apk|aab>`, short ABI
   names `armeabi`, `arm64`, `x86_64`. Example: `QRForge-arm64-v4.1.12_46-prod-release.apk`.
   An existing file of that name is replaced, with a message. Renamed files stay in Flutter's
   output folders.
6. Delete Flutter's `.sha1` for each APK.
7. Write `<file>.sha256` = `<lower-case hash>  <file name>\n`, UTF-8 without BOM
   (`[IO.File]::WriteAllText` + `UTF8Encoding($false)`).
8. Print each file with size and SHA-256, and the symbols folder to archive.
9. `finally`: `android\gradlew.bat --stop`.

Works in Windows PowerShell 5.1 and PowerShell 7. Writes only inside `build/`. Never reads
`key.properties` or the keystore.

APK and AAB builds of one version use different symbols folders (`...-apk` suffix for APK):
they are separate compiles, and each needs its own symbols to decode stack traces.

## Decisions for the user

- **A. Universal APK for prod release.** Engineering standard §5.6 and `release_process.md`
  say "no universal APK" for direct download. Recommended: refuse `-NoSplit` for `prod` +
  `release`; allow it for `dev` and for profile/debug.
- **B. Old `.sh` script.** Two scripts doing the same job will drift apart. Recommended: delete
  `tool/build_release.sh` and point every doc at the `.ps1`. (Git Bash users can still run
  `pwsh tool/build_release.ps1`.)

## Testing (no real build)

In a scratchpad folder (not this repo's `build/`): copy the script to `repo/tool/`, add
`repo/pubspec.yaml` with `version: 2.8.0+38`, and a stand-in `flutter.cmd` first on `PATH` that
logs its arguments and creates outputs with Flutter's exact names (plus `.sha1` for APKs), and a
stand-in `android/gradlew.bat`. Cases: default apk, default aab, dev debug apk, `-NoSplit` (dev),
`-NoObfuscate` on dev release, custom `-SymbolsDir`, the refused cases (exit 1, flutter not
called), missing `-Name`, rebuild of the same version, flutter failing. Check: hash equals
`Get-FileHash`, no BOM, no `.sha1` left. Run under Windows PowerShell 5.1 and parse-check under
PowerShell 7. Then `flutter analyze` is not needed (no Dart change), but the format/CI checks are
unaffected.

## Security impact

Build tooling only. No app code, permissions, network or storage change. The script never
reads signing secrets; Gradle still does the signing. Checksums make tampered direct-download
APKs easier to spot.
