# Localize all help screens (English, Malayalam, Sanskrit)

**Status:** completed

## Summary

Every help screen under `lib/screens/help/` shows hard-coded English text. The
project rules say all text a user reads must come from the ARB files through
`AppLocalizations`, in all three languages (English, Malayalam, Sanskrit). This
plan moves all help screen text into the ARB files, adds Malayalam and Sanskrit
translations, and switches the screens to read from `AppLocalizations`.

This is the "Help screens are not localized" item listed as out of scope in
`plans/20260926_220121_airqr_fountain_and_block_size_fixes.md`.

Target layers: `screens` (help screens) and `l10n` (ARB files and generated code).
No change to `models`, `providers`, or `services`.

## Issue

- 10 files in `lib/screens/help/` put user-visible English text straight into
  widgets, for example `Text('AirQR™ Optical Air-Gap Stream')` and
  `_Bullet('...')`. That is about 122 strings in the 9 topic screens plus 21 in
  the hub screen.
- Users who pick Malayalam or Sanskrit see the whole Help Center in English.
- This breaks CLAUDE.md "Localization rules" and engineering standard §8.

## Fix plan

### A. Key naming

> **Update during implementation:** the ARB files already have `help…` keys used by
> the Settings screen (for example `helpAirQrDesc`, `helpUrlTitle`). To avoid name
> clashes, the new keys use a `helpGuide…` prefix (for example
> `helpGuideAirQrIntro`), and the short app-bar titles use `titleHelp<Topic>`.
> The examples below show the original naming idea.

- All body text keys start with `help` (this prefix is "descriptive text" in
  standard §8.6, so it has no length limit and may wrap).
- Pattern: `help<Topic><Part>`. Topics: `AirQr`, `ArCodeVision`, `Barcode`,
  `Faq`, `History`, `Quishing`, `SafeBrowsing`, `SmartPayloads`, `UrlSafety`.
  Parts: `Name`, `Intro`, `<Section>Title`, `<Section>Bullet<N>`, `Tip`.
  Examples: `helpAirQrIntro`, `helpAirQrStreamingTitle`,
  `helpAirQrStreamingBullet1`, `helpAirQrTip`.
- Hub screen: `helpGroupScanning`, `helpGroupSecurity`, `helpGroupPayloads`
  (group headers) and `helpAirQrSummary` etc. (card subtitles).
- Each topic's full name (`helpAirQrName`, e.g. "AirQR™ Optical Air-Gap Stream")
  is used once on the hub card. It is shared, not copied.

### B. App bar titles (decided: short titles, the recommended option)

Standard §8.6 says app-bar titles are short text (English ≤ 20, Malayalam and
Sanskrit ≤ 22 characters). The current English titles are already too long
(for example "QuishingGuard™ Tamper Detection" is 31 characters), and the
Malayalam and Sanskrit versions would be longer still. A Material app bar shows
one line and cuts the rest with "…".

**Recommended:** add short `titleHelp<Topic>` keys for the app bars, such as
"AirQR guide", "AR CodeVision", "Barcode scanning", "URL safety",
"QuishingGuard", "Safe Browsing", "Smart actions", "History & privacy",
"FAQ & help". The full long name stays on the hub card, where it can wrap.
This is a small visible change to the English app bar text.

**Alternative:** use the long name (`help<Topic>Name`) in the app bar too, and
keep the English text exactly as it is today. Long titles will be cut off with
"…", mostly in Malayalam and Sanskrit.

### C. Screen code changes

- In each `build`, get `final l10n = AppLocalizations.of(context);` and pass
  `l10n.<key>` to `_Intro`, `_Section`, `_Bullet`, and `_Footer`.
- The `children: const [...]` lists lose `const` (the text now comes from
  `l10n`). Inner widgets such as `SizedBox` stay `const`.
- Use `package:sreeraj_qr_reader/l10n/gen/app_localizations.dart` import.
- No layout, icon, or style changes. The small private widgets (`_Intro`,
  `_Section`, `_Bullet`, `_Footer`) stay in each file as they are now.

### D. English text

- Copy the current English text into `app_en.arb` word for word.
- Keep the corrected AirQR facts from the earlier plan (already in the source
  today): LT fountain-code repair frames (not Reed-Solomon), frame rate 5 to 25
  FPS, and no chunk-size control on the transmitter screen.
- Every key gets an `@key` entry with a `description` that says which screen
  and which part it is, so a translator has context.
- FAQ items keep the question and answer in one string, split by `\n`, as they
  are now.

### E. Malayalam and Sanskrit translations

- Malayalam: natural, everyday Malayalam, correct verb forms and negation
  (§8.5.2). Use common loan words people really use (ക്യാമറ, ക്യുആർ കോഡ്,
  പാസ്‌വേഡ്) instead of forced pure-Malayalam coinages.
- Sanskrit: correct Sanskrit only, with no Hindi copulas, postpositions, or
  markers, and no nukta letters (it must pass the Hindi marker gate in
  `test/l10n/l10n_parity_test.dart`). Nominal forms for headings, polite
  imperative (e.g. `…ताम्` / `…तु`) for steps. Follow the §8.5.4 glossary where a
  term exists.
- Use the same names for app features that the ARB files already use (for
  example the existing Malayalam and Sanskrit names for AirQR, AR CodeVision,
  Settings, History).
- Keep these as they are, in Latin script, in all three languages: trademarked
  names (AirQR™, AR CodeVision™, QuishingGuard™), third-party names (Google Safe
  Browsing, Google Cloud Console, Web Risk API, UPI, BHIM, Google Pay, PhonePe,
  Paytm, Bitcoin, Ethereum, Solana), barcode format names (Data Matrix, PDF417,
  EAN-13, …), and technical tokens (`WIFI:`, `otpauth://`, `FLAG_SECURE`, JSON,
  CSV, SQLite, TOTP, FPS, `.xyz`, `bit.ly`, `console.cloud.google.com`).
- Google Cloud Console menu names ("APIs & Services", "+ CREATE CREDENTIALS",
  "API key") stay in English in quotes, because the console shows them in
  English.
- In-app places ("Settings -> Appearance") use the app's own translated names
  from the existing ARB keys.
- The change log will list the new Malayalam and Sanskrit text as "needs
  native-reader review", as standard §8.5.4 asks.

### F. Tests

- New `test/screens/help/help_screens_test.dart`: for each of the 10 help
  screens and each locale (`en`, `ml`, `sa`), pump the screen inside a
  `MaterialApp` with `AppLocalizations` delegates and the Sanskrit fallback
  delegates, and check that it builds with no exception and shows the
  localized app bar title.
- The existing parity test already checks key parity, placeholders, and the
  Sanskrit Hindi marker gate for all new keys.

### G. Checks after the change

- `flutter gen-l10n`
- `dart format .`
- `flutter analyze` (must be clean)
- `flutter test` (all pass)
- A final search in `lib/screens/help/` for leftover user-visible string
  literals.

## Out of scope

- The four small private widgets are copied in each of the 9 topic screens.
  Moving them into one shared widget file would be a good clean-up, but it is a
  separate change.
- No rewrite of the English help content (apart from the app bar titles, if the
  recommended option in B is chosen).
- A `label_length_test.dart` for the §8.6 budget does not exist in this project
  yet. Adding it is a separate change.

## Risks

- Translation quality: about 140 strings of technical prose in Malayalam and
  Sanskrit. They should be read by a fluent reader before release.
- Large ARB diff. The new keys are added as one block at the end of each ARB
  file, in the same order in all three files, so review is easier.
