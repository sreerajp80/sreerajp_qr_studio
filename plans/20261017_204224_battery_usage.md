# Reduce battery use

**Status:** completed

## The issue

The app should not drain the battery. I checked every part that keeps the
phone busy: camera, frame decoding, sensors, timers, animations, and the
background services.

**Already good (no change needed):**

- The scanner, AR CodeVision and AirQR receiver all close the camera when the
  app goes to the background, when the user leaves the Scan tab, and when
  another screen opens on top. The torch goes off with the camera.
- The Scan Bubble and GhostScan services run only when the user turns them on.
  GhostScan stops itself after one capture.
- Nothing keeps the screen awake, so the normal screen timeout still stops the
  camera.
- The clipboard check runs only when the app comes back to the front, not on a
  timer.

**Real problems found:**

1. **Light sensor is always on.** `CameraSettingsProvider` starts listening to
   the ambient light sensor when the app starts, and keeps listening on every
   screen (History, Settings, CodeForge…) for the whole time the app is open.
   It is only needed while a camera is open **and** the flash mode is "Auto".
2. **Frames are decoded with no pause.** The scanner decodes the next camera
   frame as soon as the last one is done. On a fast phone this is 30 decodes a
   second, all the time, even when no code is in view. This keeps the CPU busy
   and the phone warm.
3. **Hidden tabs keep animating.** The main screen uses an `IndexedStack`. The
   scan-frame animation on the Scan tab (a 2-second loop) keeps running at full
   frame rate while the user is on the CodeForge or History tab, where it can
   not be seen. The same animation also keeps running while scanning is
   paused.
4. **AirQR transmitter keeps going in the background.** Its frame timer (up to
   many ticks a second) does not stop when the user leaves the app.

## The fix

### 1. Light sensor only when needed

- In `CameraSettingsProvider`, do not start the sensor in the constructor.
- Add `setCameraActive(bool active)`. The provider listens to the sensor only
  while a camera is active **and** `flashMode == auto`. It stops listening when
  either one becomes false (also when the user changes the flash mode).
- The scanner and AR CodeVision screens call `setCameraActive(true)` when their
  camera starts and `setCameraActive(false)` when it stops or the screen is
  closed.
- Tests: the sensor stream is not listened to at start; it is listened to only
  when active + auto; it is cancelled on inactive or on a mode change.

### 2. Short pause between frame decodes

- In `ScanCameraController`, add a `minFrameGap` setting (default about 66 ms,
  so at most about 15 decodes a second). Frames that arrive sooner are skipped.
  15 a second still feels instant to the user.
- After about 8 seconds with no code found, use a longer gap (about 200 ms,
  about 5 decodes a second). Go back to the short gap as soon as a code is
  seen, or when the user taps to focus, zooms, or changes a camera setting.
- The AirQR receiver passes `minFrameGap: Duration.zero` and no slow-down,
  because it must catch fast-changing frames.
- Tests: frames inside the gap are skipped; the slow-down starts after the
  idle time and ends when a code is found.

### 3. Stop hidden animations

- In `MainShellScreen`, wrap each `IndexedStack` child in
  `TickerMode(enabled: index == _selectedIndex, ...)`, so animations in hidden
  tabs pause.
- In `ScanOverlayWidget`, add an `isActive` flag. The idle loop stops when the
  camera is not running (scanning paused, or camera stopped) and starts again
  when it runs. The scanner screen passes it.

### 4. AirQR transmitter pauses in the background

- Add a `WidgetsBindingObserver`. When the app goes to the background, cancel
  the broadcast timer. When it comes back, start it again if it was
  broadcasting before.

### Not changed (on purpose)

- The default camera resolution (Full HD) stays. Lower resolution reads small
  and far codes worse, and the user can already change it in camera settings.
- No "auto-pause camera after N minutes" timer: the normal screen timeout
  already turns the camera off, because the app pauses when the screen goes
  off.
