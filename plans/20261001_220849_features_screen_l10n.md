# Plan: Move Features screen text into ARB files (en / ml / sa)

**Status:** completed

## The issue

`lib/screens/features_screen.dart` keeps all of its feature text as hard-coded
English strings inside `static const List<_FeatureCategory> _categories`:

- 5 category names and 5 category subtitles,
- 26 feature titles and 26 feature descriptions,
- 78 highlight chips (3 per feature).

This breaks the project rule that all user-visible text must come from
`lib/l10n/*.arb` through `AppLocalizations`. Malayalam and Sanskrit users see
English on this screen today. Only the header card and the app bar title are
already localized (`featuresHeaderTitle`, `featuresHeaderSubtitle`,
`settingsFeaturesTitle`).

## Files to change

| File | Change |
| ---- | ------ |
| `lib/screens/features_screen.dart` | Replace the `static const` list with a `_buildCategories(AppLocalizations l10n)` method called from `build()`. |
| `lib/l10n/app_en.arb` | Add 140 new keys, each with an `@key` description. |
| `lib/l10n/app_ml.arb` | Add the same 140 keys in Malayalam. |
| `lib/l10n/app_sa.arb` | Add the same 140 keys in Sanskrit. |
| `lib/l10n/gen/app_localizations*.dart` | Regenerated by `flutter gen-l10n` (not hand-edited). |
| `change_log/<timestamp>_features_screen_l10n.md` | New change log. |

No test file needs to change. `test/screens/settings_screen_test.dart` expects
the text `SreerajP QR Reader Features`. That comes from `featuresHeaderTitle`,
which is not touched.

## Key naming

Keys are added right after `featuresHeaderSubtitle` in each ARB file.

- Categories: `featuresCat<Name>Name`, `featuresCat<Name>Subtitle`
  - `<Name>` = `Scanning`, `Safety`, `Vision`, `Payloads`, `History`.
- Features: `feature<Name>Title`, `feature<Name>Desc`,
  `feature<Name>Chip1`, `feature<Name>Chip2`, `feature<Name>Chip3`.
  - Example: `featureBarcodeEngineTitle`, `featureBarcodeEngineChip1`.

The 26 feature names: `BarcodeEngine`, `MediaSources`, `GhostScan`,
`CameraControls`, `ScanOverlays`, `Feedback`, `ProtocolGuard`,
`HomographShield`, `TldEntropy`, `IpPort`, `HeadProbe`, `SafeBrowsing`,
`QuishingGuard`, `ArCodeVision`, `AirQr`, `StegoQr`, `Wifi`, `Payments`,
`Totp`, `Contacts`, `Calendar`, `Geo`, `ScanHistory`, `Backups`,
`BiometricGuard`, `OfflinePrivacy`.

## The fix

1. **ARB (English).** Copy each English string as-is into `app_en.arb`. Each
   key gets an `@key` entry with a short description (for example
   "Features screen: chip for the barcode engine feature"). No placeholders
   are needed.
2. **ARB (Malayalam).** Natural Malayalam. Keep brand and technical tokens
   that users know in Latin script where that is normal (QR, PDF, HTTPS, UPI,
   TOTP, vCard, CSV, JSON, AirQR™, StegoQR™, QuishingGuard™, GhostScan).
3. **ARB (Sanskrit).** Classical Sanskrit, using the app's existing terms
   (`अनुप्रयोगः` for app, `अन्वीक्षणम्` for scan, `जाल-` for web/network).
   No Hindi copulas, postpositions or markers, so the text passes the Hindi
   marker gate in `test/l10n/l10n_parity_test.dart` (no `है`, `और`, `नहीं`,
   `ऐप`, `सेटिंग्स`, nukta, etc.).
4. **Chip length.** Every chip label stays ≤ 22 characters in all three
   languages. I will check this with a small script before running tests.
5. **Screen code.** In `features_screen.dart`:
   - keep the private `_AppFeature` and `_FeatureCategory` classes;
   - replace `static const List<_FeatureCategory> _categories = [...]` with
     `static List<_FeatureCategory> _buildCategories(AppLocalizations l10n)`
     that returns the same list, with every string read from `l10n`;
   - in `build()`, call `final categories = _buildCategories(l10n);` and loop
     over it. Icons and layout stay the same.
6. **Generate and check.** Run `flutter gen-l10n`, `dart format .`,
   `flutter analyze` (must be clean) and `flutter test` (all must pass).
7. **Change log.** Write `change_log/<timestamp>_features_screen_l10n.md`.

## Out of scope

- No change to the screen layout, icons, or the feature list content.
- No change to other screens.
