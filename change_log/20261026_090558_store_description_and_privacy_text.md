# Change log — Fix the StegoQR and AirQR lines in the store description, and the Safe Browsing text on the Privacy screen

Implements plan: [plans/20261026_090226_store_description_and_privacy_text.md](../plans/20261026_090226_store_description_and_privacy_text.md)

## What changed

### Store description (`play_store_private/store_listing.md` §3, git-ignored)

- **CREATE CODES:** removed "StegoQR: hide a secret message inside a normal-looking QR code,
  locked with a passphrase." The app can open StegoQR codes but cannot make them.
- **SCAN ANYTHING:** added "Opens locked codes, such as StegoQR codes with a hidden message:
  type the passphrase to see it, right on your phone."
- **SHARE WITHOUT INTERNET:** "AirQR sends files, …" is now "AirQR sends text, …". The
  transmitter has only Custom Text and Device Sync.
- New length: 2249 characters (limit 4000). "Updated" line added.

### Privacy screen text (`bodyPrivacyExplainerOff`)

Shown on Settings → Privacy & probing when Active online checks are off.

| File | Change |

| `lib/l10n/app_en.arb` | New text, and a clearer `@` description that says the text must match the code |
| `lib/l10n/app_ml.arb` | New Malayalam text (now a real translation of the English) |
| `lib/l10n/app_sa.arb` | New Sanskrit text (now a real translation of the English) |
| `lib/l10n/gen/*` | Regenerated by `flutter gen-l10n` |

- **Before (en):** "… Malicious-content lookup still uses Google Safe Browsing …". This
  suggested every link goes to Google. The code only calls Safe Browsing when the user has
  saved their own API key.
- **Before (ml, sa):** "links are never sent to outside servers". Not true when the user has
  turned on a safety service.
- **After (en):** "SSL, redirect and shortener checks use local rules only, so the scanned
  site is never contacted. A link is sent to a safety service, such as Google Safe Browsing,
  only if you turned that service on in Settings."
