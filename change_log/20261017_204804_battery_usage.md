# Reduce battery use

Implements plan: `plans/20261017_204224_battery_usage.md`

## What changed

### 1. Light sensor runs only when needed

- `lib/providers/camera_settings_provider.dart`: the light sensor is no longer
  started when the app starts. New `setCameraActive(bool)`. The sensor is read
  only while a camera is open **and** flash mode is Auto. It stops when the
  camera closes, when the flash mode changes away from Auto, and on dispose.
  When it stops, the saved lux value is cleared and the auto torch goes off.
- `lib/screens/scanner_screen.dart`: listens to the camera controller and
  tells the provider when the camera is running. Sets it to inactive on
  dispose.

### 2. Short pause between frame decodes

- `lib/services/scan_camera/scan_camera_controller.dart`: new settings
  `minFrameGap` (default 66 ms, about 15 decodes a second), `idleFrameGap`
  (default 200 ms, about 5 a second) and `idleAfter` (default 8 seconds).
  Frames that come too soon are skipped. After 8 seconds with no code and no
  user action, the slower gap is used. A found code, a focus tap, a zoom
  change, or a camera (re)start goes back to the fast gap at once.
- `lib/screens/air_qr_screen.dart`: the AirQR receiver uses zero gaps, so it
  still decodes every frame.

### 3. Hidden animations stop

- `lib/screens/main_shell_screen.dart`: each tab in the `IndexedStack` is
  wrapped in `TickerMode`, so animations in hidden tabs are paused.
- `lib/screens/widgets/scan_overlay_widget.dart`: new `isActive` flag
  (default `true`). The idle loop stops when it is false.
- `lib/screens/scanner_screen.dart`: passes `isActive` = scanning is on and
  the camera is running.

### 4. AirQR transmitter pauses in the background

- `lib/screens/air_qr_transmitter_screen.dart`: added a lifecycle observer.
  The frame timer stops when the app goes to the background and starts again
  when it comes back, if it was broadcasting.

## Different from the plan

- `lib/screens/ar_codevision_screen.dart` was **not** changed. AR CodeVision
  has its own torch button and does not use Auto flash mode, so it never needs
  the light sensor. With the new rule the sensor simply stays off there.
- The frame gap test checks the gap rule (`frameGapFor`) and the defaults. It
  does not feed real camera frames, because a `CameraImage` can not be made in
  a unit test.

## Tests

- `test/providers/camera_settings_provider_test.dart`: two new tests (sensor
  off at start, on only with camera + Auto, off on close or mode change; saved
  Auto mode does not start the sensor without a camera). The old Auto flash
  test now opens the camera first.
- `test/services/scan_camera/scan_camera_controller_test.dart`: four new
  tests for `frameGapFor`.
- `test/screens/widgets/scan_overlay_widget_test.dart`: one new test that the
  idle animation stops and starts with `isActive`.
