# Release build script with SHA-256 checksums

Plan: [plans/20261127_144519_release_script_sha256.md](../plans/20261127_144519_release_script_sha256.md)
(approved with both recommended choices: refuse `-NoSplit` for a prod release APK; delete the
old `.sh` script).

## What changed

| File | Change |
|---|---|
| `tool/build_release.ps1` | **New.** Builds APK or AAB, renames the outputs, removes Flutter's `.sha1`, writes `<file>.sha256`, prints sizes and hashes, stops the Gradle daemons. |
| `tool/build_release.sh` | **Deleted.** Replaced by the `.ps1`. |
| `docs/release_process.md` | New §6.10 (usage, options, rules, file names, checksum check, examples, what it runs with defaults). §5, §6.1, §6.4, §6.6, §8, §9, §12 and §14 updated: script commands, renamed APK paths, both symbols folders, new checklist item "every APK/AAB has a `.sha256` and no `.sha1`". |
| `CLAUDE.md`, `AGENTS.md` | Build commands now show the script first, then the raw `flutter build` commands it runs; APK symbols folder ends in `-apk`. Both files changed the same way. |
| `docs/architecture.md`, `docs/project_structure.md`, `docs/security.md` | References moved from `.sh` to `.ps1`; APK symbols folder noted. |

## Script behavior

- Options: `-Name` (required), `-Target apk|aab` (required), `-Flavor dev|prod` (default
  `prod`), `-Mode release|profile|debug` (default `release`), `-NoSplit`, `-NoObfuscate`,
  `-SymbolsDir`.
- Refused before Flutter runs (exit 1): no `+n` in the `pubspec.yaml` version; missing `-Name`
  or `-Target`; `-NoObfuscate` or `-NoSplit` for a prod release (APK); `-SymbolsDir` without
  obfuscation or outside `build/`.
- File names: `<Name>-[<abi>-]v<x.y.z>_<n>-<flavor>-<mode>.<apk|aab>`, ABIs shortened to
  `armeabi`, `arm64`, `x86_64`.
- Symbols: AAB `build/symbols/android-<flavor>-<version>/`, APK
  `build/symbols/android-<flavor>-<version>-apk/`. The AAB path is the same as before; the APK
  path is new (separate compiles need separate symbols).
- `.sha256` is `<hash>  <name>\n`, UTF-8 without BOM, so `sha256sum -c` accepts it.
- Still passes `--dart-define=BUILD_DATE=<yyyy-MM-dd>`, like the old script.

## Differences from the plan

- The hash is computed with .NET (`SHA256.Create()`), not `Get-FileHash`. In testing,
  Windows PowerShell 5.1 started from PowerShell 7 could not load the module that holds
  `Get-FileHash` (mixed module path). The result is the same hash; tests compare it with
  `Get-FileHash` run in PowerShell 7.
- The Flutter-output match uses a strict pattern (`app[-<known abi>]-<flavor>-<mode>.apk`), so a
  renamed file is never taken for a new Flutter output, even with `-Name app`.
- The docs show `powershell -ExecutionPolicy Bypass -File ...` for Windows PowerShell 5.1,
  because its default execution policy blocks scripts.

## Testing

No real build. In a scratch folder outside the repository: a copy of the script, a
`pubspec.yaml` with `version: 2.8.0+38`, a stand-in `flutter.cmd` (logs its arguments, creates
outputs with Flutter's exact names plus `.sha1` for APKs, can be told to fail) and a stand-in
`gradlew.bat`. 19 cases, run with the script under Windows PowerShell 5.1 and again under
PowerShell 7: all passed.

- Default apk, default aab, dev debug apk, `-NoSplit` (dev), `-NoObfuscate` (dev release),
  custom `-SymbolsDir` (prod profile aab, plus `-NoSplit` shown as ignored).
- Refused with exit 1 and Flutter not called: `-NoObfuscate` prod release, `-SymbolsDir`
  without obfuscation, `-SymbolsDir` in debug, `-NoSplit` prod release apk, `-SymbolsDir`
  outside `build/`, missing `-Name`, bad `-Name`, missing `-Target`, version without `+n`.
- Rebuild of the same version replaces the files with a message; `-Name app` twice works.
- Flutter failing: exit 1, nothing renamed or hashed, `gradlew --stop` still run.
- Every `.sha256` matches `Get-FileHash`, has no BOM, and `sha256sum -c` says OK. No `.sha1`
  left. The script parses with no errors in both PowerShell versions and is pure ASCII.

`flutter analyze` / `flutter test` were not run: no Dart code changed.
